# JS·React 학습 플레이그라운드

브라우저에서 코드를 고쳐 실행하며 자바스크립트와 React 를 익히는 학습 도구입니다. 설치할 것이 없고 계정도 필요 없습니다. 주소를 열면 바로 시작합니다. 레슨마다 지문을 읽고, 주어진 코드를 실행해 보고, 한 군데를 바꿔 보고, 빈 자리를 채우고, 마지막에 직접 씁니다. 채우기와 쓰기 단계는 **실제로 실행해 결과를 검사**하므로 "돌아가는 코드" 로만 통과합니다.

**→ [https://hotshin24.github.io/js-playground/](https://hotshin24.github.io/js-playground/)**

## 왜 만들었는가

웹퍼블리셔가 자바스크립트와 React 로 넘어가려 할 때, 마크업과 CSS 는 익숙한데 그 사이를 이어 주는 학습 경로가 마땅치 않았습니다. 문법 강의는 화면과 이어지지 않고, React 튜토리얼은 자바스크립트를 이미 안다고 전제합니다.

그래서 순서를 다르게 잡았습니다. **화면을 다루는 것에서 시작해 상태로, 비동기로, 앱으로 이어집니다.** 트랙 순서는 난이도가 아니라 **의존 관계**입니다. 앞 레슨에서 안 배운 것은 뒤에서 쓰지 않고, 뒤에서 쓸 것은 앞에서 반드시 다룹니다.

레슨 하나하나는 **`console.log` 로 확인하고 끝나지 않습니다.** 눈에 보이는 화면이 붙어 있고, 잘못 썼을 때 무슨 일이 일어나는지 직접 겪게 합니다.

## 어떻게 쓰는가

레슨은 **여섯 단계**로 이뤄집니다. 모든 레슨이 여섯 단계를 다 갖는 것은 아니고, 필요한 것만 씁니다.

| 단계 | 하는 일 |
|---|---|
| **읽기** | 왜 이것이 필요한지, 무엇이 새로운지 |
| **실행** | 완성된 코드를 그대로 실행해 결과를 본다 |
| **바꾸기** | 한 군데를 일부러 망가뜨려 무슨 일이 생기는지 본다 |
| **채우기** | 비어 있는 한 자리를 채운다. 검사가 붙는다 |
| **감싸기** | 채우기에서 쓴 식을 함수로 감싸, 정해진 값이 아니라 밖에서 받은 값에 통하게 만든다. 검사가 붙는다 |
| **쓰기** | 백지에서 직접 만든다. 검사가 붙는다 |

**바꾸기 단계가 이 도구의 핵심**입니다. 지문에서 "이렇게 하면 안 됩니다" 라고 말하는 대신, 직접 그렇게 해 보고 화면이 어떻게 깨지는지 보게 합니다.

완료는 관문이 아니라 기록입니다. 어느 단계로든 자유롭게 오갈 수 있고, 진행 상황은 브라우저에 저장돼 다음에 열면 이어집니다.

## 막히면 어떻게 되는가

틀리는 것이 이 도구의 사용법입니다. 그래도 같은 자리에서 계속 막히면 도구가 조금씩 손을 내밉니다.

**앞 단계에서 본 코드는 언제든 다시 볼 수 있습니다.** 채우기·쓰기 화면 아래에 `4 채우기 단계 코드 보기` 같은 버튼이 있습니다. 눌러 펼치면 그 단계의 코드가 나옵니다 — 지금 쓰던 것을 두고 앞으로 돌아갈 필요가 없습니다. 같은 레슨 안에서만 열리고, 앞에 볼 코드가 없는 단계에서는 버튼이 나타나지 않습니다.

**두 번 틀리면 힌트 버튼이 생깁니다.** 힌트는 답을 알려 주지 않습니다. 어디를 다시 보라고만 말합니다 — 어떤 값이 어디서 왔는지, 지금 코드가 무엇을 돌려주고 있는지 같은 것들입니다. 읽고 나서도 코드는 직접 생각해야 합니다. 한 단계에 최대 두 개이고 하나씩 열립니다.

**네 번 틀리면 정답 보기가 생깁니다.** 참고 답안을 펼쳐서 보여 줍니다. 편집기에 대신 넣어 주지는 않습니다 — 옮겨 적을지는 직접 정하세요.

**정답을 봐도 완료가 자동으로 붙지 않습니다.** 완료는 검사를 통과했을 때만 기록됩니다. 답을 보고 옮겨 적어 통과해도 괜찮습니다. 그것도 배우는 방법 중 하나이고, 도구는 그것을 두고 아무 말도 하지 않습니다.

힌트가 있는 단계에서는 두 번 실패한 뒤 힌트 버튼이 나타납니다. 정답 보기는 검사가 붙는 모든 단계에서 네 번 실패한 뒤 나타납니다.

## 어떻게 만들어졌는가

| 항목 | 값 |
|---|---|
| 앱 코드 | Vanilla JS · ES Modules · **빌드 없음** |
| 의존성 | **`package.json` 없음.** 필요한 것만 CDN 에서 지연 로드 |
| 편집기 | CodeMirror 6 (CDN) |
| React | iframe 안에서 UMD 개발 빌드로만 로드 |
| JSX | `@babel/standalone` — React 레슨을 처음 열 때만 받는다 |
| 실행 | `<iframe sandbox="allow-scripts">` + `srcdoc`. `allow-same-origin` 은 넣지 않는다 |
| 저장 | `localStorage` |
| 배포 | GitHub Pages (정적) |

레슨은 전부 **JSON 데이터**입니다. 레슨 하나를 추가하는 비용은 JSON 파일 1개와 목록 1줄이고, 앱 코드는 건드리지 않습니다. 다중 파일 레슨은 단계에 `files[]` 를 둡니다 — 33개 단계가 그렇습니다.

현재 학습 순서는 [`docs/CURRICULUM.md`](docs/CURRICULUM.md), 앱 동작은 [`docs/SPEC.md`](docs/SPEC.md)에 있습니다. 이전 과정의 설계와 시행착오는 역사 기록으로 보존합니다. 문서별 역할은 [`docs/README.md`](docs/README.md)에서 확인할 수 있습니다.

## 알려진 제약

- **하위 디렉터리가 없습니다.** 다중 파일 레슨(T8)의 파일은 모두 같은 자리에 나란히 놓입니다. 지정자는 `'./이름.js'` 한 가지만 받고 `'../'` 도 `'/'` 도 패키지 이름도 거부합니다. 실무에서는 폴더를 나누고 `'../components/Card.js'` 같은 경로를 쓰며, **`t8-04` 가 이 차이를 지문에서 밝힙니다.**
- **지정자 재작성이 정규식입니다.** `from '…'` 뒤의 문자열 리터럴을 찾아 `./` 를 뗍니다. 그래서 **문자열 안의 문자열도 바뀝니다.** 진짜 파서를 쓰려면 Babel 이 필요한데 순수 JS 레슨은 그 비용을 내지 않기로 했습니다. 대신 T8 레슨 소재에 그런 코드를 넣지 않습니다.
- **편집기 콜드 로드가 1,799ms 입니다.** 목표(1.5초)와 어긋나 있고 아직 손대지 않았습니다.
- **실행 틀의 제약을 무대 장치로 메운 곳이 셋 있습니다.** 샌드박스 안에서는 진짜 `fetch` 가 막히고, 폼 제출 이벤트가 발생하지 않고, 해시 링크가 프레임을 떠나게 합니다. 그래서 그 셋을 레슨 환경이 대신합니다. **학습자가 쓰는 코드는 실무와 같고**, 해당 레슨 지문이 장치의 존재와 실무와의 차이를 밝힙니다.
- **검사는 결과만 봅니다.** 클로저·이벤트 위임·`async`/`await`·`Promise.all` 처럼 "이렇게 쓰라" 를 강제하지 못하는 자리가 있습니다. 해당 레슨 지문에 그 사실을 적어 두었습니다.
- **화면 낭독기로 실제 낭독을 확인하지 못했습니다.** `aria-current`·`aria-describedby`·`aria-live` 가 붙어 있다는 것까지만 확인했습니다.
- **배경 탭에서는 일부 비동기 검사가 이른 화면을 읽습니다.** 브라우저가 배경 탭의 `setTimeout` 을 1,000ms 로 조여(실측) 가짜 응답이 늦게 도착합니다. 보이는 탭에서 어떤지는 **측정하지 못했습니다**(F-017).
