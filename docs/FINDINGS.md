## M0 검증 완료 (2026-08-19)

M0의 4개 목표와 하트비트 워치독까지 전부 실측 통과했다.
**이전 보고에서 "워치독 강제 종료 미검증" 상태로 남겨둔 항목은 해소됐다.**

### 통과 항목

| 항목 | 결과 | 측정 환경 |
|---|---|---|
| textarea 코드 → sandbox iframe 실행 | 통과. `완료 (103ms)` / 배포본 `(142ms)` | Chromium, localhost + GitHub Pages |
| `console.log` → 부모 패널 미러링 | 통과. `{name: "호진", tags: ["js", "react"]}` 직렬화·warn 색 구분 동작 | 〃 |
| 런타임 에러 + 줄 번호 | 통과. ReferenceError `(3:1)`, SyntaxError `(2:11)`, throw `(2:3)` — srcdoc 오프셋 보정 정확 | 〃 |
| 동기 무한 루프 3초 강제 종료 | 통과. `while(true)` → 프레임 제거 + 안내 문구 | 〃 |
| 비동기 무한 루프 강제 종료 (워치독) | **통과.** 테스트 A~E 5건 전부 통과, 강제 종료 실측 확인 | foreground 탭 |

### 워치독 테스트 A~E (5건 전부 통과)

| 테스트 | 코드 | 기대 동작 |
|---|---|---|
| A | `setTimeout(() => { while(true){} }, 0)` | 동기 완료 후 약 3초 뒤 "비동기 콜백이…" 종료 |
| B | `while (true) {}` | 3초 뒤 "3초 안에 끝나지 않아…" 종료 (A와 문구 분리) |
| C | `for (i<500) clearInterval(i)` + 비동기 루프 | 워치독 생존, 정상 종료 |
| D | `setInterval(() => console.log('tick'), 1000)` | 오탐 없음. 계속 출력 |
| E | D 실행 후 탭 30초 이탈 → 복귀 | 복귀 직후 오탐 종료 없음 |

### 부수 확인

- **샌드박스 격리:** iframe에서 `parent.document` → `SecurityError`, `localStorage` → `SecurityError`, `origin` → `null`. `sandbox` 속성값 `allow-scripts` 단독.
- **부모 응답성:** 6초 블로킹 루프 중에도 부모 페이지 정상 동작. Worker 전환 불필요.
- **좀비 프로세스 없음:** 강제 종료 후 16초간 `top` 4회 샘플링 — 100%에 붙은 렌더러 프로세스 없음. `frame.remove()`가 실제로 루프를 종료시킨다.
- **워치독 방어:** `clearInterval`/`clearTimeout` 래핑으로 타이머 id 무차별 해제(300회) 후에도 ping 유지. 실측 확인.

### 이 기록에 F 번호가 없는 한계 1건

블로킹 실행 중 발생한 `console.log`는 부모에 도달하지 않는다. 6초 블로킹 테스트에서 루프 직전 로그가 강제 종료까지 0건 도착, 1초 블로킹 대조군에서는 루프 종료 후 한꺼번에 도착. 자식 스레드가 막히면 `postMessage`가 플러시되지 않는다.
→ 워치독은 "멈췄다"는 사실만 알리고 "어디서 멈췄는지"는 알리지 못한다. **F 번호 미부여 — 별도 지시 대기.**

## 미해결 항목

### F-001 프레임 단위 스로틀 오탐

- **증상** — 정상 동작 중인 프레임을 워치독이 죽일 수 있다. 자식의 ping 타이머가 브라우저에 의해 지연되면 부모는 이를 "멈춤"으로 오판한다.
- **재현 조건** — 실행 프레임이 0×0 크기 + opaque origin(`sandbox="allow-scripts"`, srcdoc)인 현재 구성. 크롬은 이런 프레임의 타이머에 프레임 단위로 개입하므로 **탭이 foreground여도 발생할 수 있다.** 현재까지 실제 오탐은 미관측.
- **판단** — 부모의 `document.hidden` 가드는 **탭 단위만** 커버한다. 프레임 단위 스로틀은 막지 못한다. 이 한계를 알고 현 구성을 유지한다.
- **처리 시점** — **M1.** 미리보기 프레임이 실제 크기로 화면에 붙은 뒤 재검증한다. 프레임이 보이는 상태에서도 오탐이 나면 그때 대응한다.

### F-002 ping 실측 간격이 설정값과 다름

- **증상** — 프렐류드는 500ms 간격으로 ping을 보내도록 설정돼 있으나, 실측 도착 간격은 약 830ms다. 원인 미확정.
- **재현 조건** — 테스트 A~E 진행 중 관측. 현재 구성에서 상시.
- **판단** — 임계값 3초 대비 여유가 설계 의도인 6회분이 아니라 **3회분**이다. ping 2회만 연속으로 밀려도 오탐 사정권에 들어간다. 지금 당장 깨지지는 않으므로 값은 유지한다.
- **처리 시점** — **조건부 즉시.** F-001 재검증에서 오탐이 1건이라도 관측되면 임계값을 3초 → **5초**로 상향한다. 오탐이 없으면 현행 유지.

### F-003 워치독 안내 문구가 2갈래인데 3갈래여야 함

- **증상** — 프레임이 아예 시작하지 못한 경우(ping 0건)에도 "3초 안에 끝나지 않아… 무한 루프를 확인하세요"가 뜬다. 사용자 코드에 무한 루프가 없는데 무한 루프라고 알린다.
- **재현 조건** — 프렐류드가 실행되지 않는 상황(srcdoc 로드 실패 등). `run()` 시점의 `lastPingAt` 시드 때문에 3초 뒤 동일 경로로 종료되며, `doneSeen === false`라 sync 문구가 선택된다.
- **판단** — 현재 분기는 `doneSeen` 하나로 sync/async만 가른다. **ping을 한 번이라도 받았는지**를 나타내는 `pingSeen` 플래그를 추가해 "프레임 시작 실패"를 세 번째 갈래로 분리해야 한다.
- **처리 시점** — **M1.**

### F-004 콘솔 로그 라인 수 상한 없음

- **증상** — 부모 콘솔 패널에 쌓이는 `<li>` 노드에 상한이 없다. 대량 출력 시 DOM 노드가 무제한 증가한다.
- **재현 조건** — `while (true) console.log(1)`. 크롬은 견뎠으나 이는 우연이며 보장된 동작이 아니다.
- **판단** — 상한 **1000줄**을 두고 초과분은 앞에서 버린다(버린 사실은 표시).
- **처리 시점** — **M1.**

### F-005 `done`이 비동기 완료를 판정하지 못함

- **증상** — `done`은 동기 실행이 끝난 시점에만 발신된다. 실제 작업이 비동기인 코드는 아직 실행 중인데도 "동기 실행 완료"로 표시된다. 언제 결과를 검사해야 하는지 판단할 신호가 없다.
- **재현 조건** — `setTimeout(() => console.log('끝'), 500)` — `done`은 즉시 오고 로그는 그 뒤에 온다.
- **판단** — M0 범위에서는 의도된 축소다(`done` = 동기 실행 완료). 그러나 검증(assert)을 붙이려면 "실행이 끝났다"의 정의가 필요하다. 비동기 트랙에서는 이 신호 없이 통과/실패를 판정할 수 없다.
- **처리 시점** — **T1-8(비동기 트랙) 진입 전.** 그 전까지는 동기 레슨만 검증 대상으로 둔다.
