# CURRICULUM v2 — JavaScript에서 React까지

이 문서는 현재 배포된 **10트랙 275레슨 교육과정의 원본**이다. 이전 9트랙 113레슨을 부분 수정하지 않고, JavaScript와 React를 처음 배우는 학습자가 이 플레이그라운드만으로 개념을 연결하도록 처음부터 다시 설계했다.

참고 기준은 《한 입 크기로 잘라 먹는 리액트》의 목차와 사용자가 제시한 “자료형 설명” 수준이다. 책의 Project 1 카운터, Project 2 할 일 관리, Project 3 감정 일기장 및 그 프로젝트에 종속된 구현은 제외한다. 설치·Vite·패키지처럼 현재 정적 플레이그라운드에서 실습할 수 없는 항목은 필수 과정에서 제외한다.

## 1. 최종 목표

학습자는 과정을 마친 뒤 다음을 설명하고 작성할 수 있어야 한다.

- JavaScript의 값, 자료형, 연산, 조건, 반복, 함수, 스코프를 설명한다.
- 원시값 복사와 객체 참조의 차이를 실행 결과로 예측한다.
- 객체와 배열의 원본 변경과 새 값 생성을 구분한다.
- 콜백, Promise, `async/await`의 실행 순서를 설명한다.
- DOM과 이벤트로 HTML에 동작을 붙인다.
- JSX, 컴포넌트, props, state, ref, effect의 역할을 구분한다.
- React가 상태 변경 뒤 다시 렌더링하는 과정을 설명한다.
- `useReducer`, Context, 메모이제이션, Web Storage를 필요한 상황에 사용한다.
- 코드를 보고 “왜 이렇게 작성했는가”를 자신의 말로 설명한다.

## 2. 학습자 전제와 설명 수준

- HTML과 CSS는 작성할 수 있지만 JavaScript 변수와 함수도 모른다고 가정한다.
- 영어 오류와 개발 용어를 처음 본다고 가정한다.
- 외부 강의나 검색 없이 다음 문제를 풀 수 있어야 한다.
- 앞 레슨을 끝냈어도 개념을 즉시 기억하지 못한다고 가정한다.

핵심 개념은 `정의 → 필요성 → 가장 작은 코드 → 실행 결과 → 대조 코드 → 흔한 실수 → 다음 연결` 순서로 설명한다. 예를 들어 자료형은 `typeof 42`에서 끝내지 않는다. `typeof null`, `typeof []`, `typeof NaN`, `Array.isArray`, 원시값 복사, 객체 참조를 알맞은 시점에 다루고 React의 불변 갱신으로 연결한다.

## 3. 레슨 계약

새 개념은 다음 순서를 거친 뒤에만 문제에서 요구한다.

| 단계 | 역할 | 새 문법 |
|---|---|---:|
| 읽기 | 실제 용어·필요·작동 원리를 코드와 설명 | 1개 |
| 실행 | 가장 작은 완성형의 입력과 결과 연결 | 0개 |
| 바꾸기 | 원인 한 곳을 바꾸고 결과 비교 | 0개 |
| 채우기 | 방금 본 모양의 한 자리 복원 | 0개 |
| 감싸기 | 이미 만든 식을 함수로 일반화 | 0개 |
| 쓰기 | 같은 개념을 작은 새 문제에 적용 | 0개 |

`write`에서 처음 보는 문법이나 API를 꺼내지 않는다. 종합 레슨은 새 개념을 가르치지 않는다. “앞에서 배웠습니다”라고만 쓰지 않고 당시 코드와 핵심 문장을 짧게 복원한다.

쉬운 설명은 실제 용어를 대체하지 않는다. 첫 등장에 `반환(return — 함수가 만든 값을 호출한 자리로 보내는 것)`처럼 병기하고 이후에는 일관되게 실제 용어를 쓴다.

## 4. 제외 범위

- Project 1 카운터 앱
- Project 2 할 일 관리 앱과 해당 앱 업그레이드
- Project 3 감정 일기장과 해당 앱 리팩터링·최적화·배포
- 위 프로젝트에 포함된 React Router 실습
- VS Code·Node.js·React Developer Tools 설치 절차
- npm 패키지 생성과 Vite 프로젝트 생성 절차

라우팅, 빌드 도구, 배포는 기본 과정 이후 후속 과정 후보로 남긴다.

## 6. 반복할 설명 질문

각 핵심 단원의 마지막에는 코드 작성과 함께 다음을 묻는다.

- 이 값의 자료형은 무엇이며 왜 그런가?
- 출력과 반환은 어떻게 다른가?
- 이 함수는 누가 언제 호출하는가?
- 이 코드는 원본을 바꾸는가, 새 값을 만드는가?
- 두 변수는 값을 따로 갖는가, 같은 객체를 참조하는가?
- 이 상태를 어느 컴포넌트가 소유해야 하는가?
- 이 코드는 렌더 중 계산인가, 렌더 뒤 effect인가?
- 이 최적화는 어떤 실제 작업을 줄이는가?

## 7. 작성 금지 사항

- “앞에서 배웠습니다”만 쓰고 개념을 복원하지 않는다.
- 설명하지 않은 문법을 보조 코드에 넣고 무시하길 기대하지 않는다.
- 실제 용어를 검색할 수 없는 지어낸 말로 교체하지 않는다.
- 한 문제에서 새 API와 새 문제 해결 전략을 동시에 요구하지 않는다.
- 정답 코드가 실행된다는 사실을 학습 가능성의 증거로 쓰지 않는다.
- 면접 함정을 본 개념보다 먼저 나열하지 않는다.
- React 훅을 사용법 목록으로 외우게 하지 않는다.

## 8. 레슨 완료 기준

- 선행 개념은 이전 레슨에서 정의·실행·변경·검사를 모두 거쳤다.
- 새 용어는 첫 등장에 실제 용어와 쉬운 뜻이 함께 있다.
- `fill`과 `write`에 처음 등장하는 문법이 없다.
- 문제 전에 같은 코드 구조의 완성형을 실행했다.
- solution은 모두 통과하고 starter는 모두 실패한다.
- 학습 목표와 검사 목표가 하나로 일치한다.
- 결과를 자신의 말로 설명할 질문이 있다.
